## Contexto

La guía pide usar `developer` y ramas `feature/tp4-...` individuales para documentar los ajustes surgidos de los análisis de usabilidad y accesibilidad.

## Descripción

Verificar que `developer` exista y esté actualizada, protegerla contra pushes directos, documentar la convención de nombres y agregar una plantilla de Pull Request con checklist de revisión.

## Criterios de aceptación

- [ ] Rama `developer` creada/sincronizada con `main`.
- [ ] Protección de rama activada (al menos 1 review y checks pasando).
- [ ] Convención `feature/tp4-<tema>` documentada en el README o en `CONTRIBUTING.md`.
- [ ] Plantilla de PR con checklist (cambios, capturas, pruebas, issue vinculada).
- [ ] PRs vinculados a issues con `Closes #<n>`.

**Dependencias:** bloquea TP4-14, TP4-15 y TP4-17.
